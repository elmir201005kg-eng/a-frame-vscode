# A-FRAME KG

Сервис поиска и бронирования A-frame домиков в Кыргызстане на React 19, Vite и PostgreSQL / Prisma. Интерфейс доступен на русском, кыргызском и английском; используется локальный шрифт Manrope. Next.js удалён из зависимостей и запуска.

## Локальный запуск

Установите зависимости через `npm ci`, создайте `.env` по `.env.example` и настройте PostgreSQL. После применения миграций выполните `npm run db:generate` и `npm run dev`.

Сайт доступен по адресу [http://localhost:3001](http://localhost:3001). В режиме разработки кыргызская версия использует адреса без `/kg`; русская и английская — `/ru` и `/en`.

Демонстрационные домики видны при разработке. Для явного управления используйте `DEMO_MODE=true` или `DEMO_MODE=false`; в production без этой настройки демонстрационные объекты скрыты.

## Структура и проверки

- `app/[locale]` — главная, каталог, фотогалерея, направления, бронирование, кабинеты и административные страницы.
- `app/actions` и `app/api` — серверные действия, авторизация, доступность, оплата и загрузка фотографий.
- `components` — интерфейс; `lib` — прикладная логика и интеграции.
- `client` — запуск React в браузере и переходы между страницами; `server` — HTTP-сервер, маршруты, cookie-сессии и серверный рендеринг React.
- `vite.config.ts` — сборка; `dist` — единая папка результата. Серверные компоненты и действия React обрабатывает `@vitejs/plugin-rsc`; его API пока экспериментальный, поэтому версии закреплены в lock-файле.
- `app/i18n/locales` — переводы; `prisma` — схема, миграции и начальные данные; `tests` — автоматические проверки.

Основные команды: `npm run lint`, `npx tsc --noEmit`, `npm run test:finik`, `npm run test:ai`, `npm run build`. Проверки авторизации и административных сценариев используют отдельную тестовую БД; настройки описаны в соответствующих документах и QA-скриптах.

Production: `npm run build`, затем `npm start` (порт 3001; другой порт: `npm start -- --port 4000`). Нужен Node.js 22.13+ в ветке 22 или 24+. Старые каталоги `.next` и `.next-*` больше не используются; их можно очистить командой `npm run clean:legacy` после остановки старого сервера Next.js. Исходники и база данных этой командой не затрагиваются.

## База данных

AI-консультант с Ollama/Groq, настройка бесплатной модели и проверки: [инструкция](docs/ai-consultant.md).

Интеграция оплаты с фиксированной суммой 5 сомов: [Finik Pay](docs/finik-pay.md).

Описание общих компонентов форм, календаря, фильтров и их проверки: [система форм A-FRAME KG](docs/form-design.md).

Для A-FRAME KG подготовлена [схема Prisma](prisma/schema.prisma) на PostgreSQL: все 21 таблица из `Схема БД.md`, связи, индексы и SQL-миграции с проверками бронирований. Анализ архитектуры, ER-диаграмма и порядок подключения находятся в [prisma/README.md](prisma/README.md).

Проверка и генерация клиента: `npm run db:validate`, `npm run db:generate`. Перед применением миграций создайте `.env` по `.env.example` и укажите свой `DATABASE_URL`, затем выполните `npm run db:deploy`.

## PWA и офлайн-главная

Приложение можно установить на устройство. Иконки создаются из `public/brand/a-frame-logo.png`. После первого посещения production-сайта и загрузки офлайн-файлов главная доступна без интернета на кыргызском, русском и английском; поиск, вход и бронирование требуют подключения.

Сборка: `npm run build`, запуск: `npm run start`, проверка офлайн-режима: `npm run test:pwa`. На домене требуется HTTPS, локально подходит `localhost`. В режиме `npm run dev` service worker не регистрируется.

Анализ архитектуры, правила кеширования и инструкция установки: [docs/pwa.md](docs/pwa.md).
