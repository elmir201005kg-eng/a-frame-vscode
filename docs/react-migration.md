# Переход на React и Vite

Next.js удалён из зависимостей. `npm run dev` запускает Vite на порту 3001; `npm run build` собирает React, сервер и офлайн-страницы; `npm start` запускает Node HTTP-сервер.

Существующие страницы, стили, PostgreSQL / Prisma и интеграции сохранены. Каталоги `app/[locale]`, `app/api` и `app/actions` теперь загружает `server/routes.tsx`. Они больше не зависят от файлового маршрутизатора Next.js.

Серверные компоненты и функции относятся к React. Их компиляцию обеспечивает официальный [`@vitejs/plugin-rsc`](https://github.com/vitejs/vite-plugin-react/tree/main/packages/plugin-rsc). Этот API пока экспериментальный; версии Vite, плагинов и React закреплены. Обновлять их нужно совместно с проверкой входа, форм и гидратации.

- `client/entry.tsx` — гидратация, переходы без перезагрузки документа, запросы серверных функций и обработка истории браузера.
- Админка использует тот же React-маршрутизатор: разделы, фильтры, профиль и переключение языка открываются без перезагрузки документа. Во время перехода меню остаётся доступным; новый переход отменяет предыдущий. Если запрос страницы не отвечает 20 секунд или завершается ошибкой, панель сохраняет текущую страницу и предлагает повторить переход. Устаревший ответ не может перезагрузить уже открытую страницу. Сохранение данных и проверки доступа выполняются на сервере.
- `server/entry.rsc.tsx` — обработка HTTP-запросов, ограничения размера тела, проверка Origin и выполнение серверных функций.
- `server/context.ts` — изолированные cookie и заголовки каждого запроса через AsyncLocalStorage.
- `server/cache.ts` — ограниченный кеш публичных переводов, справочников и контактов со сбросом после изменений. Сессии и бронирования не кешируются между запросами.
- `server/start.mjs` — запуск production-сервера, раздача статических файлов, передача потоковых ответов и нескольких Set-Cookie.
- `components/image.tsx` и `/api/image` — адаптивные изображения через Sharp. Небольшие иконки загружаются напрямую.
- `scripts/build-pwa.mjs` — генерация трёх публичных офлайн-главных без чтения БД и персональных данных.

Результат сборки хранится в `dist/client`, `dist/rsc` и `dist/ssr`. Для независимой проверочной сборки можно задать `BUILD_DIR=dist-qa`; ту же переменную нужно передать при запуске сервера. Автоматические тесты используют `E2E_PRODUCTION_DIR` для выбора уже готовой сборки.

## Vercel

`vercel.json` выбирает Framework Preset **Other** (`framework: null`), выполняет `npm ci` и полный `npm run build` (включая генерацию Prisma и PWA). В Vercel сборка всегда использует `dist`; `BUILD_DIR` остаётся доступен для независимых локальных сборок.

Публикуется только `dist/client`. Файла `index.html` в корне этой сборки нет: HTML формируется сервером. RSC-запросы и изменяющие данные HTTP-методы направляются в Node.js-функцию `api/index.mjs` до проверки файлов. Затем раздаются статические файлы, а оставшиеся URL также попадают в эту функцию. Она экспортирует Web Standard `fetch` из `dist/rsc/index.js`, сохраняя исходный URL, HTTP-метод, query string, тело, заголовки RSC/Origin, cookie и потоковый ответ. `server/start.mjs` используется при `npm start` на собственном сервере; он также направляет RSC в рендерер до поиска офлайн-HTML. На Vercel HTTP listener управляется платформой.

`dist/rsc` и `dist/ssr` включены в функцию, а не в публичный каталог. Прямой импорт скомпилированной точки входа позволяет Vercel проследить зависимости Prisma/PostgreSQL и Sharp. `public/images` и `public/brand` также входят в функцию: `/api/image` и генерация иконок читают эти файлы с диска. Хешированные `/assets/*` кешируются надолго; service worker всегда перепроверяется. Три `/kg/offline`, `/ru/offline`, `/en/offline` обслуживаются из соответствующих сгенерированных HTML.

В Environment Variables Vercel задайте серверный `DATABASE_URL` с доступом к PostgreSQL, TLS и подходящим пулером, `APP_URL=https://ваш-домен` и используемые секреты Google OAuth, Telegram, `ADMIN_OTP_SECRET` и Finik. Они не должны иметь префикс `VITE_`. Миграции существующей БД выполняются отдельно через `npm run db:deploy`; сборка не меняет данные. Сессии продолжают храниться в PostgreSQL. Локальный `UPLOAD_DIR` требует долговечного хранилища: файловая система Vercel не предназначена для сохранения загруженных фотографий между вызовами.

Проверка перед повторным deploy: `npm run build`, `npm run test:deployment`, `npm run typecheck`, `npm run lint`, `npm run test:runtime`. `test:deployment` создаёт отдельную временную схему PostgreSQL через `scripts/deployment-qa.mjs`, применяет в ней миграции, добавляет фикстуру объявления и удаляет свою схему после проверки. Рабочие таблицы сайта не изменяются. Проверяются 33 публичных URL на трёх языках, SSR/RSC, Prisma, API, защита Origin, закрытые маршруты, cookie серверных действий, изображения и реальный HTTP-сервер со статическими файлами. Без `E2E_DATABASE_URL` или `DATABASE_URL` проверки страниц с БД явно пропускаются. Полные проверки входа и базы запускаются через остальные QA-скрипты с отдельными временными схемами PostgreSQL.

Публикация и настройки проекта: [docs/vercel-deployment.md](vercel-deployment.md).

В `app/globals.css` поиск классов Tailwind ограничен файлами TypeScript и TSX в `app`, `components`, `client`, `server` и `lib`. Документация, тесты и результаты проверок не участвуют в генерации CSS и регистрации её файловых зависимостей. При добавлении нового каталога с компонентами добавьте его через `@source`.

Старые процессы Next.js остановлены; `.next` и `.next-*` очищены. Команда `npm run clean:legacy` повторяет безопасную очистку только этих каталогов внутри проекта. Переменные `NEXTAUTH_URL` и `NEXT_PUBLIC_APP_URL` пока принимаются серверной интеграцией Finik для совместимости с существующими настройками; новые установки могут использовать `APP_URL`.

Проверки: `npm run typecheck`, `npm run lint`, `npm run test:runtime`, `npm run test:admin`, `npm run test:finik`, `npm run test:ai`, `npm run test:pwa`. Браузерные проверки входа, администрирования, галереи и тестового checkout используют отдельные временные схемы PostgreSQL. В `test:admin` включены проверки переходов без перезагрузки, прерывания зависшего перехода и повторной загрузки после тайм-аута (`tests/admin-navigation.spec.ts`).
