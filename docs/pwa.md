# PWA A-FRAME KG

## Архитектура проекта

- React 19 и Vite с серверными компонентами React. Корневой layout находится в `app/[locale]/layout.tsx`; `server/routes.tsx` выбирает язык, страницы и обработчики API.
- `app/i18n` содержит кыргызский (`kg`, HTML-язык `ky`), русский (`ru`) и английский (`en`) переводы. Онлайн-переводы могут переопределяться через БД.
- Главная объединяет презентационные разделы и динамический каталог. `PlatformHeader` читает сессию и избранное; `LandingExplorer` загружает домики и регионы; `SiteFooter` читает настройки контактов.
- Каталог, карточки домиков, бронирования, личный кабинет, кабинет владельца и администрирование используют серверные компоненты, Server Actions и PostgreSQL через Prisma. Их актуальные данные и операции требуют соединения.
- API обслуживает доступность дат, загрузки, фотографии, авторизацию и административные запросы. Загруженные фотографии могут иметь ограничения доступа.
- Фотографии главной, фирменный логотип и локальный шрифт находятся в `public`. Существующие E2E-тесты используют отдельную тестовую БД.

## Офлайн-режим

`components/home-content.tsx` — общая разметка обычной и офлайн-главной. `/kg/offline`, `/ru/offline`, `/en/offline` полностью создаются при сборке, используют JSON-переводы и стандартные контакты, не читают сессию или БД.

После первого посещения production-сайта service worker загружает все три офлайн-главные, фотографии, клиентские JS/CSS, шрифт, manifest и иконки. Офлайн-режим доступен после завершения установки worker; первому посещению нужен интернет.

При обычном открытии страницы worker сначала обращается к сети. При сетевой ошибке или ответе 5xx возвращает офлайн-главную нужного языка. Для `/` используется последний выбранный язык. Офлайн-страница содержит направления, описание сервиса, преимущества, FAQ и контакты. Поиск отключён, актуальные объявления и цены не отображаются; пояснение сообщает, какие действия требуют интернета. Кнопка «Попробовать снова» возвращает текущий адрес после восстановления соединения.

Офлайн-переходы выполняются загрузкой документа, чтобы маршрутизатор не ожидал недоступный RSC-ответ. Якоря, мобильное меню, FAQ и смена языка продолжают работать.

Обычный HTML, RSC, API, POST-запросы, персональные кабинеты и бронирования не сохраняются в Cache Storage. Для `/api/image` при отсутствии сети используется сохранённый оригинал публичной фотографии.

## Установка и сборка

```sh
npm run build
npm run start
```

`prebuild` создаёт PNG-иконки 192×192, 512×512, maskable 512×512 и Apple Touch 180×180 из `public/brand/a-frame-logo.png`. `postbuild` создаёт `dist/client/sw.js` со списком файлов и уникальной версией кеша. `BUILD_DIR` поддерживается. Сгенерированный worker исключён из Git; он должен входить в файлы production-развёртывания. Собирайте через `npm run build`, чтобы выполнялись оба этапа.

Manifest подключён во всём приложении, режим отображения — `standalone`. В поддерживающих браузерах появляется кнопка установки. На iPhone/iPad: Safari → «Поделиться» → «На экран Домой». Для реального домена нужен HTTPS; `localhost` подходит для локальной проверки. Подробнее о требованиях: [MDN: Service Workers](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API/Using_Service_Workers).

Worker регистрируется только в production после загрузки страницы. Новая версия ждёт закрытия вкладок предыдущей версии; после активации удаляет прежние кеши этого приложения. Старые файлы остаются доступны уже открытым вкладкам до смены worker.

## Проверка

```sh
npm run build
npm run test:pwa
```

`playwright.pwa.config.ts` запускает production-сервер на порту 3108. По умолчанию используется Chrome, `E2E_BROWSER_CHANNEL` позволяет выбрать другой установленный Chromium-браузер. Тесты не создают пользователей и не изменяют БД.

Если одновременно работает `npm run dev`, проверочную сборку лучше хранить отдельно. В PowerShell:

```powershell
$env:BUILD_DIR = "dist-pwa"
$env:VITE_PWA_WORKER_PATH = "/sw-pwa.js"
npm run build
npm run test:pwa
npm run start
```

Обе переменные должны быть одинаковыми при сборке, проверке и запуске. Здесь worker записывается в `dist-pwa/client/sw-pwa.js`; production по умолчанию использует `dist/client/sw.js`. Каталог `dist-pwa` и оба сгенерированных worker исключены из Git. Отчёты PWA сохраняются в `pwa-test-results`, отдельно от остальных E2E-тестов.

Проверяются manifest и размеры иконок, заголовки worker, офлайн-загрузка всех языков без предварительного посещения, фотографии/стили, FAQ, перезагрузка, выбор языка, запуск через `/`, переходы из недоступных кабинетов и возврат к онлайн-главной. Отдельно проверяется отсутствие приватных маршрутов в кеше. Каталоги предыдущих E2E-сборок исключены из основной проверки TypeScript, чтобы устаревшие автоматически созданные validators не блокировали текущую сборку.
