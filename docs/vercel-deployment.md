# Публикация A-FRAME KG на Vercel

## Причина 404

Проект рендерит HTML через React Server Components и SSR. `dist/client` содержит JavaScript, CSS, изображения, шрифты и офлайн-страницы. Главные страницы `/`, `/kg`, `/ru`, `/en`, каталог и кабинеты обслуживает серверная сборка. Наличие папок `client`, `rsc` и `ssr` в результате сборки само по себе не подключает обработчик HTTP-запросов.

`server/start.mjs` создаёт собственный HTTP listener для `npm start`. Vercel Functions вызывает экспортированный обработчик. Точка входа `api/index.mjs` экспортирует объект с методом `fetch` из `dist/rsc/index.js`, используя [Node.js Web Standard API Vercel](https://vercel.com/docs/functions/runtimes/node-js#create-a-node.js-function-in-/api).

## Маршрутизация

`vercel.json` задаёт Framework Preset `Other` и публикует `dist/client`. Серверные сборки `dist/rsc` и `dist/ssr`, а также исходники изображений для Sharp входят в функцию через `includeFiles`.

Порядок обработки запросов:

1. Запросы с `RSC: 1` и методы POST/PUT/PATCH/DELETE/OPTIONS передаются в функцию.
2. Обычные GET/HEAD офлайн-страниц получают сгенерированный HTML.
3. Существующие клиентские файлы раздаются Vercel как статика.
4. Остальные URL передаются в ту же серверную функцию, включая API и динамические страницы.

Это сохраняет серверные действия, авторизацию, cookie, редиректы, исходный путь и query string, а также потоковые ответы RSC/SSR. Хешированные `/assets/*` кешируются надолго, service worker перепроверяется. Серверные сборки находятся вне публичного каталога.

Корень `/` сохраняет выбор языка по cookie и `Accept-Language`: возвращает 302 на `/kg`, `/ru` или `/en`. После перехода главная возвращает 200. Закрытые страницы сохраняют редиректы на вход, а несуществующие страницы — локализованный ответ 404 приложения.

## Настройки Vercel

В Project → Settings → Build and Deployment:

| Поле | Значение |
| --- | --- |
| Root Directory | Оставить пустым |
| Framework Preset | Other |
| Build Command | Из `vercel.json`: `npm run build` с очисткой неподдерживаемых переменных npm и `BUILD_DIR` |
| Output Directory | `dist/client` |
| Node.js Version | 24.x |

Root Directory определяет расположение исходников в Git. Output Directory определяет результат сборки, который будет доступен публично. Их [настраивают отдельно](https://vercel.com/docs/builds/configure-a-build).

В Environment Variables задайте серверный `DATABASE_URL`, `APP_URL=https://ваш-домен` и секреты используемых Google OAuth, Finik, Telegram и административной авторизации. Серверные секреты не должны иметь префикс `VITE_`. Миграции существующей БД выполняются отдельно через `npm run db:deploy`.

Локальное файловое хранилище фотографий требует долговечного backend: файловая система Vercel не сохраняет загрузки между вызовами. Параметр `UPLOAD_DIR` подходит для собственного сервера или подключённого постоянного хранилища. Реальная оплата и вход во внешние сервисы требуют их production-настроек.

## Проверки и отправка

```sh
npm run build
npm run typecheck
npm run lint
npm run test:deployment
npm run test:runtime
npm run test:finik
npm run test:ai
npm run test:dependencies
```

Для полной проверки `test:deployment` нужен `E2E_DATABASE_URL` или `DATABASE_URL` с правом создавать временные схемы в мигрированной PostgreSQL с `btree_gist`. Тесты работают только в своей случайной QA-схеме и удаляют её после выполнения. Без подключения к БД соответствующие проверки явно пропускаются. Проверка оплаты использует тестовые ответы и не выполняет реальных платежей.

После проверки подготовленного коммита отправьте ветку:

```sh
git push origin main
```

На Vercel откройте новый deployment, созданный из отправленного коммита. В поле Source должен быть его новый SHA. Кнопка Redeploy у старого deployment повторно собирает его старый исходный код, поэтому проверяйте SHA перед запуском.

После публикации проверьте `/`, `/ru`, `/en`, каталог и карточку объявления, статические файлы `/assets/*`, а также редиректы кабинетов на вход. Локальные production-проверки подтверждают работу сборки и функции; проверка реального домена требует нового deployment с этими изменениями.
