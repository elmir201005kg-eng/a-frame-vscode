# Демонстрационный каталог A-FRAME KG

Добавляемый набор содержит ровно 8 вымышленных A-Frame домиков. У каждого есть описания, населённый пункт, условный адрес и правила на русском, кыргызском и английском; английские названия используются как имена концептов во всех трёх версиях. По уточнению пользователя прежние 30 демо-объектов остаются опубликованными: после добавления новых восьми публичный каталог содержит 38 домиков. Существующие объявления, их статусы, пользователи и история бронирований/платежей сохраняются.

У каждого концепта есть регион из существующего справочника, город или село, условный адрес с номером `DEMO-01`…`DEMO-08`, вместимость и количество спален, кроватей и ванных. У каждого домика три иллюстративных фотографии из `public/images`. Источники новых фото сохранены в `public/images/demo-photo-credits.json`; они не подтверждают существование объекта аренды.

## Запуск

Используется серверный `DATABASE_URL` из `.env` или окружения. Не публикуйте его и не используйте клиентские `VITE_*` переменные для подключения к БД.

```powershell
npm run db:seed:demo -- --dry-run
```

Проверка работает только на чтение, в том числе до применения миграции. **До записи в рабочую базу необходимо отдельное подтверждение владельца сайта.** Выбор количества публичных домиков не является таким подтверждением. После подтверждения:

```powershell
npm run db:generate
# Только если dry-run сообщает migrationRequired: true:
npm run db:deploy
npm run db:seed:demo -- --confirm-eight-demo-cabins
```

`--dry-run` проверяет модель БД, владельца и занятые slug, сообщает `wouldCreate`, существующие количества записей, необходимость миграции и подробный план восьми новых домиков, не записывая данные. Проверка выполняет SELECT в транзакции READ ONLY. Без флага записи команда отказывается изменять базу. Запись выполняется с явным флагом `--confirm-eight-demo-cabins`. После повторного запуска ожидаются `created: 0`, `existing: 8`, `enriched: 0`. Ранее созданные объявления не архивируются и не скрываются.

Скрипт сам добавляет недостающие регионы и удобства. Он не запускает общий seed, не переименовывает и не активирует отключённые справочники. Один PostgreSQL transaction и advisory lock защищают от частичных записей и одновременных запусков. Занятый чужим объектом slug, конфликт владельца или общая с чужим домиком локация приводят к откату всех изменений. Владельцу используется адрес в зарезервированном домене `.invalid`; новые учётные данные для входа не создаются.

Для существующих объектов основного набора seed блокирует бронирование, заполняет пустые населённые пункты, заменяет только старый адрес-заглушку, добавляет отсутствующие удобства и правила. Пользовательские тексты, цены и фотографии сохраняются. Изменённый вручную или архивированный концепт не публикуется повторно.

Seed работает только с восемью slug из `prisma/demo-cabins.ts`. Существующие домики вне этого списка не изменяются. Все строки, фотографии, локации, бронирования и платежи сохраняются. В админке можно менять тексты, цены, характеристики, фотографии и статус новых домиков. Изменение цены или названия сохраняет переводы адреса, описания правил и запрет бронирования.

## Хранение и показ

Миграция `20261027000100_demo_showcase` добавляет nullable-переводы населённых пунктов, адресов и правил, а также `Cabin.isBookable` с `DEFAULT true`, сохраняя прежнее поведение существующих объектов. Набор получает `isDemo=true`, `isBookable=false`, `status=PUBLISHED`. Новые тексты хранятся в PostgreSQL через Prisma; клиент получает локализованные DTO. При отсутствии перевода обычного объявления используется русский текст.

Опубликованные концепты видны в каталоге, поиске, карточках и админке даже при `DEMO_MODE=false`. Проверки активного региона и подтверждённого активного владельца сохраняются. Поиск учитывает названия на трёх языках, регион, город/село и адрес. Применяются существующие фильтры цены, гостей, удобств и дат, сортировка и пагинация. В админке сохраняются поиск переведённых названий, статус и пагинация.

Публичная карточка показывает маркировку «Демо» и сообщение о недоступности реального проживания. Для `isBookable=false` отсутствуют формы выбора дат и оплаты. Прямой переход на checkout, server actions, `quoteStay`/`createBooking`, availability API и создание/повтор оплаты Finik также блокируются. Существующие бронирования и платежи сохраняются; обработка уже полученных квитанций остаётся доступной для сверки истории. Флаг `DEMO_MODE=true` не снимает запрет с этих восьми объектов. У прежних заявок на недоступные для бронирования концепты кнопки оплаты также скрыты.

Галерея каждого нового домика содержит три фотографии: экстерьер A-Frame, интерьер и пейзаж Кыргызстана. Это иллюстрации концепта, а не снимки сдаваемого жилья. Экстерьеры восьми домиков различаются; часть интерьеров и пейзажей используется повторно. Новые стоковые фотографии получены по бесплатной [Unsplash License](https://unsplash.com/license), пейзажи — CC0 или CC BY-SA. Автор, исходная страница и лицензия каждой фотографии сохранены в `public/images/demo-photo-credits.json` и доступны под галереей на трёх языках. Для изображений CC BY-SA показаны сведения об изменении размера/формата и сохранении лицензии.

## Проверки

```powershell
npm run typecheck
npm run lint
npm run test:runtime
npm run test:finik
npm run test:ai
npm run test:demo-catalog
```

`test:demo-catalog` создаёт случайную схему `aframe_showcase_qa_*` в `E2E_DATABASE_URL` (или `DATABASE_URL`), применяет миграции и выполняет проверки seed и браузера. Проверяются отсутствие дублей при повторном и одновременном запуске, сохранность пользователя/объявления/бронирования, откат конфликтов, запрет изменения отключённых справочников, полнота переводов, поиск/фильтры/сортировка/пагинация и запрет бронирования/оплаты. Браузер открывает каталог и карточки на трёх языках, проверяет админку и прямые обращения к checkout/API. После запуска удаляется только созданная им случайная схема.

Для проверки только БД: `npm run test:demo-catalog -- --database-only`. Для браузера с production-сборкой задайте `E2E_PRODUCTION=true`, `E2E_PRODUCTION_DIR` и соберите с тем же `BUILD_DIR`. Данные рабочего сайта тестами не изменяются.

Сравнение проверенных файлов с рабочими исходниками не обнаружило различий.

Повторная проверка рабочей схемы только на чтение обнаружила уже существующие восемь запрошенных домиков. У каждого `PUBLISHED`, `isDemo=true`, `isBookable=false`, три фотографии, пять правил и переводы описания на KG/EN. Всего в рабочих таблицах: 38 домиков, 11 пользователей, 13 бронирований, 9 платежей. Последний dry-run: `existing: 8`, `wouldCreate: 0`, `migrationRequired: false`, конфликтов нет. Команда записи с `--confirm-eight-demo-cabins` в этой работе не запускалась; повторная вставка не требуется.
