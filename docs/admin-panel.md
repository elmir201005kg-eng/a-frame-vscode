# Административная панель A-FRAME KG

Панель расширяет существующее приложение Next.js 16.4, PostgreSQL / Prisma 7,
систему переводов и дизайн сайта. Новый проект и отдельная база не создавались.

## Доступ и маршруты

Точка входа: `/admin`. После входа доступны `/ru/admin`, `/kg/admin`, `/en/admin`.
Вход требует пароль и одноразовый код Telegram. Обычный пользователь, владелец,
отключённый аккаунт и сессия без подтверждения второго фактора доступа не получают.

| Маршрут после `/[locale]/admin` | Возможности |
| --- | --- |
| `/` | Реальные показатели, графики, последние брони, активности и уведомления |
| `/analytics` | Аналитика за сегодня, 7, 30, 90 дней, год или выбранный период |
| `/activities` | События платформы с поиском и фильтром дат |
| `/cabins` | Поиск, статусы, создание, редактор, фотографии, публикация, архив, удаление |
| `/categories` | Категории на трёх языках, привязка к домикам, редактирование и удаление |
| `/bookings` | Таблица, поиск, статусы брони и оплаты, фильтры дат, история, подтверждение, отмена |
| `/calendar` | Занятость по домикам и месяцам, блокировка, открытие и техобслуживание |
| `/payments` | История реальных записей платежей, поиск, фильтры, потоковый CSV-экспорт |
| `/users` | Контакты, роли, состояние аккаунта и история бронирований |
| `/reviews` | Публикация, скрытие и модерация отзывов; пересчёт рейтинга в транзакции |
| `/promotions` | Скидки и промокоды с периодом действия; применение в серверной цене брони |
| `/notifications` | Личные события администратора и отметка прочитанного |
| `/messages` | Отправка сообщений пользователям через существующие уведомления сайта |
| `/translations` | Переопределения JSON-переводов в БД с проверкой параметров строки |
| `/settings` | Контакты сайта, включение бронирований, уведомления, профиль, пароль и сессии |
| `/audit` | Журнал административных изменений с сохранёнными значениями |
| `/owners`, `/regions`, `/amenities` | Существующие справочники и проверка владельцев |

Sidebar сворачивается на desktop и открывается как модальный Drawer на мобильных.
Горизонтальная прокрутка широких таблиц ограничена контейнером таблицы.

## Сохранение данных и правила

- Миграция `20261015000100_admin_workspace` добавляет категории, связи с домиками,
  поле промокода и роль `SUPER_ADMIN`. Миграция применена к текущей БД без сброса данных.
- Административный редактор использует существующий сервис домиков и загрузки файлов.
  Публичная карточка получает название, цену, описание, фотографии и категории из той же БД.
- Домик с историей бронирований или отзывов удалить нельзя: используйте архивирование.
- Пересечения бронирований запрещены исключающим ограничением PostgreSQL.
  Операции календаря и бронирования берут одну блокировку строки домика.
- Конец диапазона календаря не включается. Техобслуживание хранится как `BLOCKED`
  с пометкой `maintenance:`; публичный сервис доступности учитывает его сразу.
- Отмена действует в пределах `cancelUntil`. Полученная оплата требует отдельного
  урегулирования возврата; панель не подделывает возврат или статус провайдера.
- Автоматическая акция не требует кода. При вводе кода проверяются домик, активность
  и даты всего проживания. Скидки не складываются: применяется самая большая.
  Итог и размер скидки сохраняются как неизменяемый снимок бронирования.
- Платёжные статусы обновляет существующий проверенный webhook Finik. Ручной кнопки
  «сделать платёж успешным» нет. CSV защищён серверной авторизацией и экранированием формул.
- Только `SUPER_ADMIN` меняет административные роли. Последний активный администратор
  и последний активный `SUPER_ADMIN` защищены; изменение роли или блокировка отзывает сессии.
- Регистрация допускает только `USER` и `OWNER`. Ключи и пароли не передаются в браузер.

## Первоначальная настройка SUPER_ADMIN

Для нового аккаунта укажите в приватном окружении `ADMIN_EMAIL`, `ADMIN_PASSWORD`,
`ADMIN_NAME`, при необходимости `ADMIN_PHONE`, и `ADMIN_ROLE=SUPER_ADMIN`.
Запустите `npm run db:create-admin`. Команда не перезаписывает существующие аккаунты.
Действующие администраторы автоматически не повышаются в правах.

## Изменённые области кода

- `components/admin-workspace.tsx` — подключение рабочих разделов;
  `admin-cabins`, `admin-calendar`, `admin-reservations`, `admin-taxonomy`,
  `admin-people`, `admin-settings`, `admin-communications` — страницы разделов.
- `components/admin-workspace-ui.tsx`, `admin-action-form.tsx`, `admin-recent-events.tsx`,
  `admin-shell.tsx`, `admin-dashboard*.tsx` и `app/[locale]/(administration)/admin/admin.css`
  — интерфейс, подтверждения, уведомления и адаптивность.
- `app/actions/admin-workspace.ts`, `admin.ts`, `owner.ts`, `photos.ts` — операции с данными.
- `lib/admin-policy.ts`, `roles.ts`, `auth.ts`, `admin-two-factor.ts`, `google-auth.ts`
  и существующие проверки ролей в маршрутах — общая политика административного доступа.
- `lib/admin-filters.ts`, `csv.ts`, `app/api/admin/payments/export/route.ts` — фильтры и экспорт.
- `lib/booking.ts`, `admin-events.ts`, `finik-payments.ts`, `app/actions/traveler.ts`,
  `auth.ts` — скидки и атомарные события платформы.
- `prisma/schema.prisma`, миграция, `scripts/create-admin.ts`, `.env.example` — схема и настройка.
- `app/i18n/locales/{ru,kg,en}/{admin,common}.json` — переводы интерфейса.
- Изменения публичной части ограничены необходимой связью с админкой: категории в карточке,
  поле промокода, применение скидки, контакты в футере и проверка роли `SUPER_ADMIN`.

## Проверки

`npm run lint`, `npx tsc --noEmit`, `npm run test:finik`, `npm run test:admin`.
Последняя команда собирает production-версию в `.next-admin-production` и проверяет
её в браузере, используя новую случайную схему `aframe_qa_*`. После тестов схема
удаляется. Фото тестов сохраняются отдельно от настоящего хранилища.
Скриншоты: `test-results-admin/admin-desktop.png` и `admin-calendar-mobile.png`.

## Ограничения интеграций

- Текущая интеграция Finik списывает фиксированные **5 KGS**. Это существующее поведение
  сохранено. Выручка отражает фактически полученные суммы, а не полную стоимость проживания.
  Конфигурация ключей не подтверждает доступность провайдера; реальное списание при разработке
  не выполнялось. Возвраты через API провайдера в проекте не реализованы.
- Входящей системы поддержки в проекте нет. Раздел сообщений использует уведомления сайта;
  он не выдаёт их за email, чат с оператором или систему тикетов.
- Фотографии используют существующее файловое хранилище `UPLOAD_DIR`. В production ему
  нужен постоянный записываемый диск либо отдельная интеграция объектного хранилища.
- Свободный пользовательский текст переводится через поля KG / RU / ENG вручную.
  Журнал технических событий и снимки JSON сохраняют машинные имена полей для аудита.
