# Аудит производительности A-FRAME KG

**Статус: исправления внесены; итоговая проверка остановлена из-за параллельной смены стека.** В начале аудита проект использовал Next.js 16.4. Во время работы другие изменения заменили его на Vite: изменены `package.json` и lock-файл, пакет Next.js удалён из `node_modules`, появились `vite.config.ts` и заготовки `server/`. Эти изменения не выполнены в рамках данного аудита. На момент обнаружения `npm run start` обращается к отсутствующему `server/start.mjs`, а Vite config — к отсутствующим entry-файлам. Ниже результаты относятся к проверенной версии на Next.js; переносить их на новую версию нельзя.

Проверяется существующая рабочая копия проекта. Незакоммиченные изменения, которые были до аудита, сохранены. Production-сборка и браузерные сценарии запускаются локально; рабочие аккаунты и бронирования не изменяются. Записи автоматических тестов изолированы в случайных временных схемах PostgreSQL.

## Стек и маршруты

Next.js 16.4.0, React 19.3.0, TypeScript, App Router, Server Components, Cache Components и Partial Prefetching. Данные: PostgreSQL, Prisma 7.10 и `@prisma/adapter-pg`. Интерфейс: собственные CSS, Radix UI, локальный Manrope. Есть RU/KG/EN, PWA, Google OAuth, Telegram, Finik Pay и AI-консультант.

Публичные адреса сохранены. Главная `/{locale}` теперь находится в `app/[locale]/(platform)/page.tsx` и использует общий layout с каталогом, портфолио, направлениями, инструкцией, документами, входом, регистрацией, личным кабинетом, карточками, бронированиями и кабинетом владельца. Административные маршруты остаются в отдельной группе `(administration)`. Группа в скобках не входит в URL.

## Найденные причины и исправления

| Причина | Подтверждение | Исправление |
| --- | --- | --- |
| Много сетевых обращений при чтении связей Prisma | Для одной краткой карточки зарегистрированы 6 SELECT, для подробной — 11. Сетевой SELECT 1 занимал около 200–220 мс после подключения | Генератор Prisma включает `relationJoins`: связанные данные возвращаются одним SQL-запросом. Структура таблиц и миграции не меняются |
| Последовательные независимые запросы | Каталог сначала ждал COUNT и избранное, затем запрашивал карточки; главная ждала справочники перед выборкой домиков; footer последовательно читал два набора контактов | Независимые чтения выполняются параллельно. Для URL со страницей за пределами каталога сохранён переход к последней странице |
| Все второстепенные данные задерживали карточку | До вывода названия и основной фотографии ожидались календарь, отзывы и похожие домики | Отзывы, актуальный календарь бронирования и рекомендации выводятся отдельными Server Components через Suspense. Данные календаря обязательны до включения формы |
| При медленном переходе с главной исчезало меню | Регрессионный сценарий удерживает RSC-ответ каталога; прежняя главная теряла весь header и показывала общий skeleton | Главная и остальные публичные страницы используют один layout. Header сохраняется, переход можно прервать другой ссылкой |
| Ссылки подвала на телефоне перекрывал AI | Playwright зафиксировал `intercepts pointer events` при обычном клике по условиям использования | Внизу страницы зарезервировано место, позволяющее прокрутить ссылки выше плавающих кнопок |
| Повторные обновления оплаты могли накладываться | В компоненте был безусловный `router.refresh()` каждые 3 секунды | Новый запрос не запускается, пока идёт предыдущий; скрытая вкладка не опрашивается; ручная кнопка отражает настоящее состояние запроса. Запрос создания оплаты имеет timeout и отменяется при уходе |
| Часть JavaScript загружалась до необходимости | Словарь AI импортировался кнопкой запуска, просмотрщик фотографий — вместе с галереей | Кнопка получает только две строки своего языка с сервера. Полный словарь AI и просмотрщик загружаются при открытии соответствующего интерфейса |
| Лишняя работа форматирования | Каждый вызов форматирования создавал новый объект Intl | Повторно используются форматтеры чисел, множественного числа и даты Bishkek; кеш числовых форматтеров ограничен 32 вариантами |
| Избыточный размер отдельных изображений | Desktop hero выбирал ширину 1920 при контейнере около 1280 px | Добавлена ширина 1440 и уточнены `sizes` главного фото и миниатюр. Основной hero сохраняет preload; первое фото портфолио загружается приоритетно, последующие — lazy |
| Шум в Console и проверках | Браузер запрашивал отсутствующий `/favicon.ico`; lint проверял сгенерированные отчёты; typecheck включал старые валидаторы маршрутов из прошлых сборок | Явный `/icon` в metadata, отдельные папки отчётов, исключение устаревших дополнительных сборок из TypeScript |

`relationJoins` в установленной Prisma 7 является Preview-функцией генератора. Её действие и стратегии описаны в [официальной документации Prisma](https://docs.prisma.io/docs/orm/v7/prisma-client/queries/relation-queries). Скрипт SQL-аудита сравнивает результаты обеих стратегий и завершится ошибкой, если они отличаются.

Ссылки уже использовали обёртку над `next/link`, GET-формы — `next/form`; заменять их не требовалось. Рабочие зависимости не удалялись: безопасно неиспользуемых тяжёлых runtime-пакетов не найдено. PWA оставляет API, мутации и RSC сетевыми; общий кеш персональных данных, сессий, платежей и доступности не добавлялся. React `cache()` для переводов действует в пределах серверного рендера.

## Измерения

SQL-замеры выполняет `npm run audit:database`. Он делает только SELECT, не выводит параметры или реквизиты подключения, сравнивает одинаковые данные с `query` и `join` и сохраняет `performance-results/database.json`.

Исходный диагностический прогон показал прогретое чтение краткой карточки за 614 мс против 204–205 мс с JOIN; подробной — за 611–615 мс против 203–298 мс. Число SQL-запросов сократилось с 6/11 до 1. Это результат конкретного локального подключения, а не обещание для любого сервера.

Первые браузерные замеры воспроизвели каталог за 1,7–1,9 с и карточку за 2,6–4,4 с. После первого набора исправлений desktop-карточка отображалась примерно за 0,5–0,8 с. Эти предварительные результаты включают накладные расходы автоматизации и не используются как строгий процент ускорения.

CPU-профиль обнаружил существенные расходы генерации accessibility-снимков самим Playwright на замедленном мобильном профиле. Финальный измеритель ожидает готовность внутри браузера, отсчитывает переход от настоящего клика и отдельно сохраняет Network, Chrome trace, long tasks, Event Timing, LCP, CLS и показатели памяти после GC. Полный CPU-профиль включается только через `PERFORMANCE_CPU_PROFILE=true`, поскольку он тоже влияет на замер.

Ранние сырые браузерные трассы находились в `test-results` и были очищены стандартным runner при запуске функциональных тестов. Их численные результаты выше взяты из вывода команд. Новые измерения сохраняются отдельно в `performance-results` и переживают повторный запуск тестов.

Проверки до обнаружения смены стека:

- Production-сборки Next.js завершались успешно: 102 страницы, генерация PWA worker.
- ESLint и TypeScript проходили без ошибок на версии Next.js.
- Finik и AI: 57 модульных проверок прошли; SSR-локализация форм: ещё 6 прошли.
- Новый production-набор: прошли 3 проверки сохранения меню при задержанном RSC-ответе, кликов по мобильным ссылкам и отсутствия наложений polling оплаты. Добавленная позже проверка чрезмерно большого номера страницы ещё не запускалась на финальном коде.
- Первый полный браузерный прогон: 43 passed, 10 failed, 4 skipped, 4 did not run. В нём проверены 46 маршрутов на семи ширинах и 72 сочетания языка и ширины без горизонтального переполнения. Найдены конфликты общей тестовой БД, устаревшие сценарии подтверждения, скрытых полей и проверки готовности потоковой страницы. Runner и соответствующие тесты исправлены; окончательный прогон не завершён.
- PWA: 4 passed, 4 failed. Выявлена ошибка гидратации AI-виджета при подстановке офлайн-HTML по обычному адресу. Виджет перенесён из корневого layout в онлайн-оболочку; исправление требует повторной сборки и проверки.
- Последующие тестовые запуски после изменения `package.json` перестали стартовать: отсутствует `server/start.mjs`. Эти результаты не характеризуют производительность исправленной версии Next.js.

Аудит нельзя считать полностью завершённым до выбора целевой версии проекта и успешных проверок её финального состояния.

## Запуск и повторная проверка

Команды ниже предназначены для версии на Next.js и требуют восстановления её зависимостей и npm scripts. Текущая незавершённая конфигурация Vite использует другие точки входа.

С корректной `.env` для версии Next.js:

```powershell
npm run db:generate
npm run lint
npm run typecheck
npm run build
npm run start -- --port 3115
```

Открыть `http://localhost:3115/ru`. В отдельном терминале:

```powershell
npm run audit:navigation -- current
npm run audit:database
npm run test:performance
npm run test:pwa
```

`PERFORMANCE_URL` задаёт адрес для read-only замеров; по умолчанию это `http://localhost:3115`. Полный QA-runner использует `E2E_DATABASE_URL` либо создаёт временные схемы на подключении `DATABASE_URL`; ему нужны права на создание схем и уже установленное расширение `btree_gist`. Каждый spec получает собственные данные и сервер, отчёты — `test-results-performance`. Можно выбрать файлы через `QA_FILES`, например `navigation-performance.spec.ts,responsiveness.spec.ts`. Finik checkout с подменённым провайдером имеет отдельную команду `npm run test:demo-checkout`.

Для production-показа существующих демо-домиков перед запуском сервера можно задать `$env:DEMO_MODE='true'`; реальные данные для этого не создаются.

Мобильная проверка — эмуляция Chrome с мобильным viewport/Touch/DPR и замедлением CPU, а не измерение на физическом телефоне. Production build не содержит React development Profiler: использованы Chrome Performance/CPU/Network и функциональные регрессии. Реальная оплата и вход в настоящий Google-аккаунт не выполняются.
