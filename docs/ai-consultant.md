# AI-консультант A-FRAME KG

В сайт встроен плавающий чат RU / KG / ENG. Серверный endpoint — `POST /api/ai/chat` в существующем Next.js App Router. Дополнительный сервер приложения и новые зависимости не нужны.

## Подключение бесплатной модели

### Ollama, локально

Установите [Ollama](https://ollama.com/download) на компьютер, на котором работает сервер Next.js. В терминале:

```powershell
ollama pull qwen2.5:3b
ollama serve
```

Если Ollama уже запущена в трее, второй `ollama serve` не нужен. `qwen2.5:3b` — компактная модель; [страница модели](https://ollama.com/library/qwen2.5:3b) содержит размер и варианты. Скорость зависит от памяти и процессора/GPU. Модель 1.5b можно выбрать на слабом компьютере, но качество кыргызского языка и следования инструкциям может снизиться.

Добавьте к существующему `.env` эти строки, сохранив текущие настройки PostgreSQL и остальных интеграций:

```dotenv
AI_PROVIDER="ollama"
OLLAMA_BASE_URL="http://127.0.0.1:11434"
OLLAMA_MODEL="qwen2.5:3b"
AI_TIMEOUT_MS="45000"
AI_TRUST_PROXY="false"
```

Перезапустите Next.js. Локальный API Ollama описан в [официальной документации](https://docs.ollama.com/api/chat); приложение использует `stream: false` и [структурированный JSON](https://docs.ollama.com/capabilities/structured-outputs).

При размещении сайта на другом сервере `127.0.0.1` указывает на этот сервер, а не на компьютер посетителя. Запустите Ollama на сервере приложения либо задайте доступный ему закрытый адрес. В Docker для Ollama на хосте может понадобиться `http://host.docker.internal:11434`. Не публикуйте незащищённый порт Ollama в интернете.

### Groq Free Plan

Создайте ключ в [Groq Console](https://console.groq.com/keys) в аккаунте на Free Plan. Укажите:

```dotenv
AI_PROVIDER="groq"
GROQ_API_KEY="ваш_ключ_только_на_сервере"
GROQ_MODEL="llama-3.1-8b-instant"
AI_TIMEOUT_MS="45000"
AI_TRUST_PROXY="false"
```

Перезапустите приложение. Параметры моделей и бесплатные лимиты могут меняться: проверьте [доступные модели](https://console.groq.com/docs/models) и [лимиты своего аккаунта](https://console.groq.com/docs/rate-limits). Приложение не подключает платный тариф и не переключается автоматически на другого провайдера. Бесплатность определяется тарифом аккаунта Groq; не включайте платный тариф для этого сценария. Диалог и публичные сведения домиков при таком выборе отправляются Groq; с Ollama они остаются на вашем сервере. Политика провайдера: [Your Data](https://console.groq.com/docs/your-data).

HTTP 429/503 от модели переводит ответ в явно обозначенную справку. `Retry-After` передаётся клиенту. Внутренние ошибки сервиса, ключи и сырые ответы провайдера посетителю не показываются.

### Только справка

```dotenv
AI_PROVIDER="faq"
```

Чат показывает «Справка · без AI» и предупреждение, что модель недоступна. Этот режим не выдаётся за генерацию. Справка о домиках всё равно использует текущую базу сайта.

## Запуск и проверки

```powershell
npm install
npm run dev
# http://localhost:3001/ru

npm run test:ai
npm run test:ai:ui
npx tsc --noEmit
npm run lint

npm run build
npm run start -- --port 3001
```

`.env.example` содержит все переменные без ключей. Не копируйте его поверх уже настроенного `.env`. Для существующей мигрированной базы дополнительные миграции не нужны.

Модульные тесты подменяют PostgreSQL и сетевые ответы модели, проверяя оба протокола, три языка, отказы, историю, даты, приватность, XSS, недостоверные числа, таймаут/прерывание и лимиты. Они не оценивают качество реальной установленной модели.

Браузерные тесты запускают отдельный Next.js на порту 3127 в `.next/ai-qa`, используют Chrome и реальный endpoint в режиме FAQ. Проверяют три языка, перезагрузку, очистку, мобильный экран, ошибки сети и отсутствие дублей. Они не создают аккаунты, домики или брони. При подключённой базе endpoint обновляет только одну служебную строку лимита в существующей `auth_throttles`. Нужен установленный Google Chrome; канал можно изменить через `E2E_BROWSER_CHANNEL`.

Для ручной проверки реальной модели откройте чат и задайте «Сколько стоит аренда домика?». Только успешно полученный и прошедший проверку ответ модели помечается «Ответ AI». Остановите Ollama или временно выберите `AI_PROVIDER=faq` и убедитесь, что ответ помечен справкой. Проверьте кыргызский и английский язык с выбранной моделью: качество зависит от её языковых возможностей.

## Данные и ограничения

- Публичные домики выбираются через `publicCabinWhere`: опубликованный объект, проверенный владелец, активный аккаунт и регион, действующие настройки деморежима. Демонстрационные объекты явно помечены.
- В контекст попадают только название, локализованное описание, базовая цена, расположение, вместимость, активные удобства и правила, часы заезда/выезда и срок отмены. Контакты владельцев, пользователи, административные настройки и персональные данные брони не загружаются.
- На странице домика запрос привязан к его `slug`. В общем каталоге подбираются до четырёх публичных объектов; это ограниченная подборка, а не проверка всего каталога.
- Даты «сегодня/завтра», `today/tomorrow`, `бүгүн/эртең` считаются по `Asia/Bishkek`. Также поддерживаются ISO-даты `YYYY-MM-DD`, число гостей и число ночей. Для сложных дат вроде «в следующие выходные» чат просит точные даты. Проверка ограничена 30 ночами; для более долгого периода используйте форму сайта. Без количества гостей проверяется один гость, для относительной даты без выезда — одна ночь.
- Для доступности и итоговой стоимости вызывается `quoteStay` — та же функция, что в `/api/availability`, с календарными тарифами, занятыми датами и действующими автоматическими акциями. Промокоды чат не применяет; их следует вводить в форме бронирования. Доступность повторно проверяется при оформлении.
- При недоступной базе чат честно сообщает об отсутствии точных данных. Цены и свободные даты не заменяются фиктивными предложениями.
- Finik Pay в текущем проекте списывает фиксированные **5 KGS**; это не полная стоимость проживания. Ответ о платеже использует `FINIK_PAYMENT_AMOUNT` из существующего кода.
- Чат не выполняет действий с бронированиями и оплатой. Личные брони открываются через `/[locale]/account`, затем через существующие страницы с авторизацией и проверкой прав.

## Защита и хранение

Сервер ограничивает тело запроса 24 000 байт, вопрос — 1200 символами, историю — 12 сообщениями. Клиент посылает только последние шесть пользовательских вопросов. Браузерные сообщения с ролью `assistant` никогда не используются как доказанные факты или инструкции; `system` и `developer` отклоняются.

Проверка тематики и распространённых prompt injection выполняется до вызова модели. Дополнительно модель классифицирует запрос и обязана вернуть структурированный ответ со ссылками на идентификаторы серверных фактов. Ответ проверяется на допустимые источники, неподтверждённые числа, опасную разметку, чужие URL и утверждения об успешно выполненных операциях. Ошибочный результат заменяется справкой. Это несколько уровней защиты; качество свободного текста зависит от модели, и семантические ошибки требуют проверки при выборе/смене модели.

Ключ Groq доступен только серверному модулю с `server-only`. Пользователь не выбирает upstream URL, модель или провайдера. Вывод — обычный текст React, без `dangerouslySetInnerHTML` и произвольного Markdown/HTML. Ссылки формирует сервер, клиент дополнительно допускает только существующие публичные пути. Межсайтовые запросы запрещены; ответы API имеют `Cache-Control: no-store, private`.

В PostgreSQL атомарно учитывается общий бюджет **24 разрешённых запроса в минуту** между всеми экземплярами приложения, без IP и переписки. Дополнительно действуют локальный ограничитель и максимум два параллельных запроса к модели на процесс. При `AI_TRUST_PROXY=false` локальный лимит общий; при `true` — 12 запросов/мин на IP из `X-Forwarded-For`. Включайте `true` только если доверенный reverse proxy полностью заменяет этот заголовок. Дополнительный сетевой лимит на reverse proxy полезен для многосерверного размещения.

История хранится в `sessionStorage`, отдельно для каждого языка, максимум 20 сообщений, и исчезает при закрытии вкладки или очистке чата. Телефоны и email посетителя маскируются до отправки и сохранения. Пользовательские имена и прочие сведения в свободном тексте невозможно надёжно автоматически распознать; интерфейс просит не отправлять личные данные. Сервер не сохраняет диалоги и не пишет их в логи.

## Файлы

- `app/api/ai/chat/route.ts` — endpoint, чтение ограниченного тела, origin и лимиты.
- `lib/ai/{shared,policy,knowledge,provider,chat,rate-limit}.ts` — типы, редактирование контактов, тематика, данные, провайдеры, ответы и защита нагрузки.
- `app/i18n/ai.ts` — все тексты RU/KG/ENG.
- `components/{ai-consultant,ai-chat-panel,ai-mark}.tsx`, `app/ai-widget.css` — интерфейс и стили с отдельным префиксом классов, совместимые с CSS-загрузчиком проекта.
- `app/[locale]/layout.tsx` — подключение виджета и стилей.
- `.env.example`, `package.json` — конфигурация и команды.
- `tests/ai.test.ts`, `tests/ai-ui/chat.spec.ts`, `playwright.ai.config.ts`, `playwright.config.ts` — проверки и разделение тестовых наборов.
- `tsconfig.json` — Next.js автоматически добавляет типы отдельной проверочной сборки.
- `README.md`, `docs/ai-consultant.md` — документация.
