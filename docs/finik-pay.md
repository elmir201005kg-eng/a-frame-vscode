# Finik Pay

Переход с кнопки «Создать тестовую заявку» проверяется командой `npm run test:demo-checkout`: браузер создаёт заявку в отдельной временной схеме БД, получает тестовый ответ Finik и открывает страницу оплаты на 5 KGS. Проверяются повторная попытка после ошибки провайдера и сохранение дат при входе. Реальные платежи в этой проверке не создаются.

Интеграция основана на `FINIK_INTEGRATION_GUIDE.md`. Сумма платежа фиксирована: **5 KGS** (`lib/finik-config.ts`). Цены проживания в каталоге и бронировании сохраняются отдельно; они не используются при создании платежа.

В демонстрационном домике кнопка «Создать тестовую заявку» создаёт заявку и сразу открывает Finik Pay для оплаты 5 сомов. Тестовая заявка и её оплата не предусматривают реального проживания и подтверждения владельцем. Если переход к оплате не удался, заявку можно открыть в личном кабинете и повторить оплату из её деталей.

В деталях своей реальной или тестовой заявки гость также может нажать «Оплатить 5 сом». `POST /api/finik/create-payment` принимает `{ "bookingId": "123", "locale": "ru" }`, проверяет сессию и принадлежность брони, сохраняет UUID платежа и возвращает URL из ответа Finik `302 Location`. Сумма и пользователь определяются на сервере. Отменённые, отклонённые и уже оплаченные брони недоступны для оплаты.

`POST /api/finik/webhook` проверяет `signature`, `x-api-timestamp` (не старше пяти минут), сумму, аккаунт и связь UUID с бронированием. Подпись проверяется и в beta, и в prod по исходному телу запроса. Статусы `success` и `succeeded` принимаются в любом регистре и нормализуются в `SUCCEEDED`: устанавливаются `PAID`, ID транзакции и дата оплаты. `FAILED`/`failed` устанавливает `FAILED`. Повторные уведомления не дублируют записи и не понижают статус полученной оплаты. После неудачной оплаты доступна новая попытка. Получение денег после отмены записывается и создаёт уведомление о необходимости возврата. Подтверждение проживания остаётся действием владельца.

Возврат на `/{locale}/bookings/{id}?payment=success` ожидает webhook и обновляет страницу. Сам redirect не подтверждает оплату. Запрос, не получивший ответ от Finik, можно повторить спустя 30 секунд с прежним UUID; готовая ссылка переиспользуется.

Ссылка страницы оплаты из `302 Location` может содержать `status=failed` ещё до оплаты. Этот параметр не означает отказ создания платежа: ссылка сохраняется и передаётся браузеру без изменения. Итоговый статус устанавливается только после проверки подписанного webhook. Для открытия сайта через туннель в режиме разработки `next.config.ts` разрешает hostname настроенного публичного адреса в `allowedDevOrigins`.

При создании платежа `Origin` должен совпадать с `Host` страницы или с настроенным публичным адресом сайта. Поэтому сайт можно открывать на `localhost`, а публичный HTTPS-адрес в `APP_URL` использовать для уведомлений Finik и возврата после оплаты. Запросы с посторонних сайтов отклоняются.

Переменные в `.env`: `FINIK_ENV` (`beta`/`prod`), `FINIK_API_KEY`, `FINIK_ACCOUNT_ID`; в prod также `FINIK_PRIVATE_KEY` в формате PEM. Адрес сайта выбирается из `NEXTAUTH_URL`, затем `NEXT_PUBLIC_APP_URL`, затем `APP_URL`. Без этих переменных используется Origin входящего запроса после проверки совпадения с Host. За reverse proxy передавайте исходный Host или задайте канонический адрес: внутренний адрес Next.js не должен попасть в webhook/redirect. При заданном каноническом адресе его Host используется для проверки подписи webhook. Для prod необходим HTTPS. Для получения webhook при локальном запуске нужен публичный адрес туннеля, указанный в одной из этих переменных.

Добавлена миграция `20261013000300_finik_pay`: UUID провайдера и ссылка оплаты в `payments`. При развёртывании выполните `npm run db:deploy` и `npm run db:generate`.

Проверки: `npm run test:finik`, `npm run lint`, `npm run build`. Автоматические тесты используют тестовые RSA-ключи и подменённый HTTP/БД; реальные платежи не создаются. Для полной проверки Finik выполните оплату и дождитесь подписанного webhook на публичном сервере.

## Полная проверка оплаты

1. Используйте публичный HTTPS-домен сайта или HTTPS-туннель к локальному порту 3001. Укажите его origin в `APP_URL`; если заданы `NEXTAUTH_URL` или `NEXT_PUBLIC_APP_URL`, они имеют приоритет и должны соответствовать тому же адресу. Перезапустите сервер после изменения `.env` и открывайте сайт через этот HTTPS-адрес.
2. Для проверки без реального списания используйте `FINIK_ENV=beta` с отдельными тестовыми реквизитами Finik. В `prod` проводится реальный платёж на 5 KGS. Наличие ключей в `.env` не подтверждает их действительность.
3. Войдите как гость и нажмите «Создать тестовую заявку» на странице опубликованного демонстрационного домика. Должна открыться страница Finik с суммой 5 KGS. Для реального домика создайте бронь и откройте её детали; бронь должна ожидать подтверждения или быть подтверждена, ранее полученной оплаты быть не должно.
4. Завершите оплату на странице Finik. При повторной попытке или для реальной брони используйте кнопку «Оплатить 5 сом» в деталях заявки. Созданный платёж использует webhook `${APP_URL}/api/finik/webhook`; адрес берётся с учётом приоритета переменных выше.
5. Убедитесь, что запрос Finik к webhook получил HTTP 200, а в админке в разделе платежей появились статус `PAID`, сумма 5 KGS, ID транзакции и дата оплаты. Сверьте запись с кабинетом Finik. Возврат на сайт с `payment=success` сам по себе не подтверждает получение денег.

Документация провайдера: [режимы и публичный Callback URL](https://www.finik.kg/documentation/web-sdk/reference/), [форматы webhook](https://www.finik.kg/documentation/web-sdk/webhooks/).
